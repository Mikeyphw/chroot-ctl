# Python → Go compatibility contracts

`migration/contracts/v1/` is the frozen GO00 baseline captured from the former Python backend. It remains checked into source control as immutable migration evidence even though the production repository is now Go/Kotlin-only.

The baseline contains:

- `cli.json`: the 83-node human CLI tree (including first-class `version`) plus the separate `chrootctl app` CLI, argument metadata, defaults, choices, and help text.
- `bridge.json`: protocol-v1 limits, redaction rules, all 91 allowlisted bridge operations, their mode/destructive/lock metadata, and accepted payload fields.
- `persistence.json`: SQLite schema/PRAGMAs, operation journal schema and JSON fields, terminal/active states, and stable Android/legacy config locations.
- `foundations.json`: GO03 model field names, validation outcomes/error text, deterministic config defaults/overrides, structured error payloads, and logging behavior frozen from the former implementation.
- `release.json`: the frozen release identity used to validate the completed Go cutover.
- `python-registry.sqlite3.fixture`: a frozen Python-created SQLite registry used only as data by the GO02 real-device Go compatibility probe.

The Python exporter was deliberately removed in GO17. These v1 fixtures are no longer regenerated by production tooling. An intentional post-cutover contract change must update the relevant fixture explicitly, update the Go/Kotlin implementation and tests, and update the migration ledger in the same reviewed change. Incidental drift is a validation failure.

`repoctl validate` checks the frozen fixtures and live Go contract metadata. `repoctl final-seal` repeats that check as part of the release seal.
