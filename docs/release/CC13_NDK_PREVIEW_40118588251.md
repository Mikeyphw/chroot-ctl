**Source base:** GitHub Chrootctl `55b4513470e6e455944310805ea248d3b04756a8` (CC12). **Scope:** source-only hotfix; no native Android release is qualified by local tests.

## Observed authoritative failure
GitHub Actions run `https://github.com/Mikeyphw/chroot-ctl/actions/runs/40118588251` (job `dual-release`, ID `120945024746`): checkout, Go setup, Android SDK setup, pinned Devtool bootstrap and 19-node plan succeeded. `ci-release` stopped at `chrootctl_hosted_release.preflight`, reporting `FAIL_HOSTED_RELEASE_preflight: NDK revision differs`. Summary: 0 passed, 1 failed, 18 skipped; no uploaded artifacts. The log did not expose the inspected `source.properties` path or its observed revision, so whether an inherited path, trailing whitespace or incorrect installed metadata caused the initial mismatch is **not independently determined**.

## Root-level cause and fix
The old `ensure_ndk()` used `${ANDROID_NDK_HOME:-$ANDROID_HOME/ndk/$NDK_REV}` and compared the value from whichever NDK that selected with an exact untrimmed shell string. It therefore permitted ambient `ANDROID_NDK_HOME` to select a different NDK than the reviewed SDK installation. Worse, its failure message hid the actual path/value.

The new `scripts/ci/require-hosted-ndk.sh` selects **only** the installed `$ANDROID_HOME/ndk/29.0.14206865` side-by-side NDK, independently of ambient `ANDROID_NDK_HOME` and `ANDROID_NDK_ROOT`. It requires an ordinary readable `source.properties` with exactly one `Pkg.Revision`; trims CRLF/whitespace; verifies an exact `29.0.14206865` value; requires the NDK ARM64 API-26 clang; rejects linked top-level NDK roots and linked metadata/compiler entries. The stage exports this pinned path for native build consumers and prints the path, revision and API in its success message. On validation failure, a human-readable fail-closed diagnostic includes the expected/actual values and path. Nothing automatically falls back to r28/r27 or the host compiler.

## Regression verification
`bash scripts/ci/test-require-hosted-ndk.sh` covers: correct pin with deliberately incorrect inherited NDK variables; CRLF metadata; revision mismatch; duplicate/missing metadata; missing or unexecutable target compiler; API-24 request. The test runs inside `test-verifier` on the hosted Devtool DAG. No network/SDK download is needed for these negative tests.
